# 프로젝트명
AI 2D 슈팅 프로토타입

# 게임 개요
플레이어가 탑뷰 시점에서 적의 공격을 회피하고 사격으로 돌파하는 3D 탑뷰 슈팅 프로토타입 게임이다. 빠른 플레이 감각 검증과 핵심 전투 루프 확인을 목표로 한다.

# 핵심 컨셉
## 한 줄 컨셉
짧은 이동, 즉각적인 사격, 빠른 회피로 전투 리듬을 검증하는 탑뷰 슈팅 프로토타입.

## 플레이 감각
- 이동은 가볍고 즉시 반응한다.
- 공격은 짧고 명확하게 체감된다.
- 회피와 사격이 계속 교차된다.

## 전투 방향
- 다수의 적을 빠르게 정리한다.
- 좁은 탄막 사이를 이동한다.
- 안전 위치를 짧게 판단한다.

## 프로토타입 목표
- 이동과 사격의 기본 손맛 확인
- 탑뷰 전장 가독성 확인
- 짧은 전투 루프의 반복 재미 검증

# 핵심 메커니즘
## 시스템 목적
- 이동, 사격, 충돌의 기본 루프를 빠르게 검증한다.
- 짧은 전투 한 사이클이 자연스럽게 이어지는지 확인한다.

## 1. 플레이어
### 시스템 설명
- 이동
  - 플레이어는 XY 평면에서만 이동한다.
  - 방향 입력을 받으면 상하좌우와 대각선으로 즉시 반응한다.
  - 이동 속도는 고정값을 사용한다.
- 공격
  - 공격 입력을 누르면 플레이어 앞에서 총알 1발을 발사한다.
  - 연사는 버튼 홀드 또는 짧은 간격 반복 발사 중 하나로 단순하게 구현한다.
  - 발사 방향은 화면 위쪽으로 고정한다.
- 피격
  - 적과 부딪히면 플레이어 HP가 감소한다.
  - 피격 직후 짧은 무적 시간은 선택 사항으로 둔다.
  - HP가 0이 되면 플레이어는 죽는다.

### 체크리스트
- 플레이어는 XY 평면 밖으로 이동하지 않는다.
- 입력 직후 이동 반응이 바로 보인다.
- 공격 입력 시 총알이 바로 생성된다.
- 적과 충돌 시 HP가 감소한다.
- HP 0 상태를 확인할 수 있다.

## 2. 플레이어의 총알
### 시스템 설명
- 이동
  - 총알은 생성 직후 화면 위로 단순 이동한다.
  - 속도는 고정값을 사용한다.
  - 화면 밖으로 나가면 제거한다.
- 충돌
  - 적과 부딪히면 총알은 제거된다.

### 체크리스트
- 총알은 항상 위쪽으로 이동한다.
- 총알 속도는 일정하다.
- 화면 밖 총알이 정리된다.
- 적과 충돌 시 총알이 제거된다.

## 3. 적(AI)
### 시스템 설명
- 이동
  - 적은 플레이어를 향해 단순 추적 이동한다.
  - 이동은 XY 평면으로 제한한다.
  - 여러 적이 동시에 접근해도 기본 동작이 유지된다.
- 공격
  - 기본 프로토타입에서는 몸통 충돌 자체를 공격으로 본다.
  - 적이 플레이어에게 닿으면 플레이어 HP를 감소시킨다.
- 피격
  - 플레이어와 부딪히면 적은 죽는다.
  - 플레이어의 총알과 부딪혀도 적은 죽는다.

### 체크리스트
- 적이 플레이어 방향으로 이동한다.
- 적 이동이 XY 평면에 유지된다.
- 적과 플레이어 충돌 시 플레이어 HP가 감소한다.
- 적과 플레이어 충돌 시 적이 제거된다.
- 적과 총알 충돌 시 적이 제거된다.

## 4. 기본 전투 루프
### 시스템 설명
- 플레이어는 이동으로 위치를 조정한다.
- 플레이어는 위쪽으로 총알을 발사한다.
- 적은 플레이어에게 접근한다.
- 충돌이 발생하면 HP 감소 또는 제거 처리한다.
- 이 흐름을 짧은 시간 안에 반복 검증한다.

### 체크리스트
- 이동, 사격, 적 접근이 한 화면 안에서 바로 확인된다.
- 전투 흐름이 10초 이내에 반복된다.
- 충돌 결과가 즉시 보인다.
- 디버그 없이도 플레이 감각 확인이 가능하다.

# 기술 명세
## 1. 플레이어 이동
### 생성할 클래스 구조
- 클래스명: `JC_PlayerController`
- 부모 클래스: `MonoBehaviour`
- 역할: Old Input 입력을 받아 플레이어를 XY 평면에서 이동시킨다.

### 검증원칙
- 이동은 X, Y 좌표만 변경하고 Z는 고정한다.
- 입력이 들어온 프레임부터 바로 반응하는지 우선 확인한다.
- 대각선 이동 속도가 과하게 빨라지지 않도록 정규화 여부를 확인한다.

### 응답원칙
- 입력이 없으면 즉시 정지한다.
- 입력이 있으면 고정 속도로 바로 이동한다.
- 화면 기준 이동 방향은 항상 동일하게 유지한다.

## 2. 플레이어 사격
### 생성할 클래스 구조
- 클래스명: `JC_PlayerShooter`
- 부모 클래스: `MonoBehaviour`
- 역할: 공격 입력을 받아 플레이어 앞에서 총알 프리팹을 생성한다.
- 클래스명: `JC_BulletSpawnPoint`
- 부모 클래스: `MonoBehaviour`
- 역할: 총알 생성 위치 기준점을 Inspector에서 지정할 수 있게 한다.

### 검증원칙
- 공격 입력 시 총알이 지연 없이 생성되는지 확인한다.
- 연사 간격이 Inspector 값대로 유지되는지 확인한다.
- 총알 생성 위치가 플레이어 중심과 겹치지 않는지 확인한다.

### 응답원칙
- 공격 입력이 들어오면 조건 확인 후 즉시 발사한다.
- 연사 제한 시간 중에는 추가 발사를 막는다.
- 발사 방향은 화면 위쪽으로 고정한다.

## 3. 플레이어 총알
### 생성할 클래스 구조
- 클래스명: `JC_PlayerBullet`
- 부모 클래스: `MonoBehaviour`
- 역할: 총알을 위쪽으로 이동시키고 충돌 또는 화면 이탈 시 제거한다.

### 검증원칙
- 총알이 생성 직후 위쪽으로만 이동하는지 확인한다.
- 속도가 프레임에 따라 달라지지 않는지 확인한다.
- 적 충돌과 화면 이탈 시 모두 정상 제거되는지 확인한다.

### 응답원칙
- 생성되면 즉시 전진한다.
- 적과 충돌하면 바로 제거된다.
- 전장 밖으로 나가면 바로 정리된다.

## 4. 적 추적 이동
### 생성할 클래스 구조
- 클래스명: `JC_EnemyController`
- 부모 클래스: `MonoBehaviour`
- 역할: 플레이어 위치를 기준으로 적을 XY 평면에서 단순 추적 이동시킨다.
- 클래스명: `JC_EnemyTargetTracker`
- 부모 클래스: `MonoBehaviour`
- 역할: 추적 대상인 플레이어 Transform 참조를 유지한다.

### 검증원칙
- 적이 항상 플레이어 방향으로 이동하는지 확인한다.
- Z축이 흔들리지 않고 평면 이동만 유지되는지 확인한다.
- 적 수가 늘어나도 기본 추적 동작이 깨지지 않는지 확인한다.

### 응답원칙
- 대상이 있으면 즉시 추적 이동한다.
- 대상이 없으면 이동하지 않는다.
- 이동 방향 계산은 단순하게 유지한다.

## 5. 충돌과 체력 처리
### 생성할 클래스 구조
- 클래스명: `JC_Health`
- 부모 클래스: `MonoBehaviour`
- 역할: 플레이어 HP 감소와 사망 상태를 관리한다.
- 클래스명: `JC_DamageOnContact`
- 부모 클래스: `MonoBehaviour`
- 역할: 적이 플레이어와 충돌했을 때 피해를 적용한다.
- 클래스명: `JC_DestroyOnHit`
- 부모 클래스: `MonoBehaviour`
- 역할: 총알 또는 적이 충돌 조건을 만족하면 제거 처리한다.

### 검증원칙
- 적과 플레이어 충돌 시 HP가 1회만 감소하는지 확인한다.
- HP가 0이 되면 사망 상태가 즉시 반영되는지 확인한다.
- 총알과 적 충돌 시 양쪽 제거 조건이 충돌 없이 동작하는지 확인한다.

### 응답원칙
- 피해 조건이 맞으면 즉시 HP를 감소시킨다.
- 사망 조건이 되면 즉시 제거 또는 비활성 처리한다.
- 충돌 결과는 한 번에 한 가지 결과로 명확히 처리한다.

## 6. 전투 흐름 조립
### 생성할 클래스 구조
- 클래스명: `JC_GameplaySceneBinder`
- 부모 클래스: `MonoBehaviour`
- 역할: 플레이어, 적 프리팹, 카메라, 참조 오브젝트를 씬에서 빠르게 연결하고 검증한다.

### 검증원칙
- 필수 참조가 비어 있으면 플레이 시작 전에 바로 확인할 수 있어야 한다.
- 플레이어, 총알, 적 흐름이 한 씬에서 바로 반복 테스트 가능해야 한다.
- 디버그 도구 없이도 전투 루프 확인이 가능해야 한다.

### 응답원칙
- 씬 진입 시 필요한 참조를 먼저 점검한다.
- 누락된 참조는 빠르게 찾을 수 있게 단순하게 드러낸다.
- 전투 루프 확인을 방해하는 복잡한 초기화는 넣지 않는다.
